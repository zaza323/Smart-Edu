# بنك الأسئلة التفاعلي — Smart Edu Pro

تطبيق مستقل بالكامل عن الموقع القديم، يتشارك معه **مشروع Firebase فقط** (`smart-edu-pro-d012b`).
مبني وفق وثيقة المتطلبات (PRD v1.0).

```
question-bank/
├── web-app/              تطبيق React (Vite + Tailwind) — واجهة الطالب والأدمن
├── functions/            Cloud Functions (Node.js) — كل المنطق الحسّاس
├── scripts/              سكربتات إدارية (تعيين أدمن، استيراد أسئلة بـ Node)
├── firestore.rules       قواعد أمان Firestore
├── firestore.indexes.json الفهارس المركّبة
├── storage.rules         قواعد Storage (إثباتات الدفع)
└── firebase.json         إعدادات النشر
```

## 1) المتطلبات قبل البدء

| المتطلب | ملاحظة |
|---|---|
| Node.js 20+ | مثبّت لديك ✅ (v24) |
| Firebase CLI | `npm install -g firebase-tools` ثم `firebase login` |
| **تفعيل Firestore** | Firebase Console → Firestore Database → Create database (وضع Production، الموقع `eur3` أو الأقرب) |
| **خطة Blaze** | Cloud Functions تتطلب خطة Blaze (الدفع حسب الاستخدام). الاستخدام المتوقع لمنصة بهذا الحجم يبقى ضمن الحصة المجانية غالباً، لكن التفعيل إلزامي. |

## 2) خطوات التشغيل الأولى (بالترتيب)

### أ) تنصيب الاعتماديات

```bash
cd question-bank/web-app && npm install
```

```bash
cd question-bank/functions && npm install
```

```bash
cd question-bank/scripts && npm install
```

### ب) نشر قواعد الأمان والفهارس

> ⚠ **قبل النشر:** افتح `storage.rules` واقرأ التحذير في أعلى الملف — نشره كما هو
> يستبدل قواعد Storage الحالية وقد يقطع الوصول لملفات PDF الخاصة بالمعلمين.
> الصق قواعدك الحالية في القسم المخصّص داخل الملف أولاً.

```bash
cd question-bank && firebase deploy --only firestore:rules,firestore:indexes
```

### ج) نشر Cloud Functions

```bash
cd question-bank && firebase deploy --only functions
```

### د) تعيين حساب الأدمن

1. سجّل حساباً عادياً من التطبيق بالبريد الذي تريده أدمن.
2. نزّل مفتاح حساب الخدمة: Firebase Console → ⚙ Project Settings → Service accounts → Generate new private key، واحفظه باسم `scripts/serviceAccountKey.json`.
3. نفّذ:

```bash
cd question-bank/scripts && node set-admin.js your-email@example.com
```

4. سجّل خروجاً ودخولاً مجدداً ليأخذ الحساب الصلاحية، وسيظهر زر «الإدارة».

### هـ) إضافة أول مادة

من لوحة الأدمن → **المواد والأسعار** → «مادة جديدة»:

| الحقل | مثال |
|---|---|
| معرّف المادة | `islamic-11-s1` (إنجليزي صغير + شرطات — يُستخدم في الروابط والاستيراد) |
| اسم المادة | التربية الإسلامية |
| الصف / الفصل | الحادي عشر / الفصل الأول |
| السعر | 10 |
| دقائق لكل سؤال | 1 |

ثم املأ **بيانات التحويل** في أسفل نفس الصفحة (تظهر للطالب في صفحة الاشتراك).

### و) استيراد أول دفعة أسئلة

**من ملف Word:** ارفعه مباشرة من لوحة الأدمن ← المواد والأسعار ← «استيراد أسئلة»
على بطاقة المادة. التفاصيل في القسم 9.

**من ملف JSON جاهز:**

```bash
cd question-bank/scripts && node import-questions.js "C:/Users/mhmdz/Downloads/questions_sample.json" --subject-id islamic-11-s1 --lesson-number 1 --dry-run
```

احذف `--dry-run` بعد مراجعة التقرير لتنفيذ الرفع فعلياً.

### ز) اختبار الأمان الشامل (اختياري لكن مفيد بعد أي تعديل على القواعد)

```bash
cd question-bank/scripts && node e2e-test.js
```

ينشئ حساب طالب تجريبي، ويتحقق آلياً من معايير القبول التسعة (منع الوصول قبل التفعيل،
منع قراءة `questions` مباشرة، عدم تسريب الإجابة الصحيحة، صحة التصحيح الخادمي، منع
التسليم المكرر، منع تزوير الدرجة أو الاشتراك، حماية دوال الإدارة)، ثم **يحذف الحساب
وكل بياناته** في النهاية.

```bash
cd question-bank/scripts && node e2e-storage-test.js
```

يتحقق من قواعد Storage: أن دوسيات المعلمين ما زالت تُقرأ، وأن الطالب لا يستطيع الكتابة
في جذر الحاوية، وأن رفع الإثبات يعمل للصور فقط داخل مجلد الطالب نفسه دون غيره.

### ح) التشغيل محلياً والنشر

```bash
cd question-bank/web-app && npm run dev
```

```bash
cd question-bank && firebase deploy --only hosting:question-bank
```

> النشر يستخدم موقع Hosting منفصل باسم `smart-edu-question-bank`. أنشئه أولاً من
> Firebase Console → Hosting → Add another site، أو غيّر الاسم في `.firebaserc`.

## 4) كيف تُطبَّق متطلبات الأمان (القسم 9 من الـ PRD)

| المتطلب | التطبيق |
|---|---|
| منع قراءة `questions` من العميل | `firestore.rules`: الطالب لا يملك `get` ولا `list` على المجموعة إطلاقاً. الوصول حصراً عبر `startExam` التي تتحقق من الاشتراك أولاً. |
| عدم إرسال الإجابة الصحيحة أثناء الاختبار | `startExam` و`resumeExam` تعيدان `questionText` و`optionsText` فقط — `correctAnswerIndex` لا يغادر الخادم إلا بعد التسليم. |
| تصحيح من طرف الخادم | `submitExam` تقرأ الأسئلة بـ Admin SDK وتحسب الدرجة وتكتبها في `attempts`. العميل لا يملك أي صلاحية كتابة على `attempts`. |
| منع تزوير الاشتراك | `users` تسمح للطالب بتعديل `fullName` و`phone` فقط؛ `subscriptions` و`role` تُكتب من Cloud Functions حصراً. |
| صلاحية الأدمن | Custom Claim (`request.auth.token.admin`) تُضبط من `set-admin.js` — لا يمكن تزويرها من المتصفح. |
| رفع الإثباتات | `storage.rules`: صور فقط، أقل من 5MB، داخل مجلد الطالب نفسه. |

## 5) نموذج البيانات المطبَّق

```
users/{uid}            fullName, phone, email, role, createdAt,
                       subscriptions: { [subjectId]: { status, subjectName, activatedAt, activatedBy, expiresAt } }

subjects/{subjectId}   name, grade, semester, description, price, minutesPerQuestion, active,
                       questionCount, lessons: [{ number, title, count }]   ← تُحدَّث آلياً عند الاستيراد

questions/{docId}      subjectId, subject, grade, semester, lesson, lessonNumber, questionNumber,
                       questionText, optionsText[4], correctAnswerIndex, explanation, difficulty,
                       sourceCohortYear, random, createdAt
                       (docId = sha1(subjectId|lessonNumber|نص السؤال|نصوص الخيارات) → يمنع التكرار تلقائياً)

paymentRequests/{id}   uid, subjectId, subject, amount, proofImageUrl, proofPath, status,
                       rejectionReason, submittedAt, reviewedAt, reviewedBy

attempts/{id}          uid, subjectId, subject, lessonNumber, lessonLabel, questionIds[],
                       studentAnswers[], answeredCount, score, totalQuestions, percentage,
                       timeTakenSeconds, autoSubmitted, status, review[], startedAt, submittedAt

questionStats/{qId}    subjectId, questionText, timesShown, timesCorrect, timesWrong
settings/payment       accountName, bankName, iban, wallet, note

leaderboard/{uid}      fullName, grade, subjectScores: { [subjectId]: number }, updatedAt
                       ← مجموعة عرض عامة للوحة الأبطال (تفاصيلها في القسم 8)
```

**تنبيه مهم حول منع التكرار:** بصمة `docId` تشمل **نصوص الخيارات** وليس نص السؤال وحده،
لأن بنك الوزارة يحتوي أسئلة مختلفة تشترك في نفس نص السؤال وتختلف في الخيارات فقط
(في عيّنة التربية الإسلامية: الأسئلة 13/14 و27/28 و30/31). الاعتماد على نص السؤال وحده
كان يدمجها ويُضيع 3 أسئلة من كل 86.

**فرق مقصود عن الـ PRD:** الحقل `random` أُضيف لتمكين سحب عيّنة عشوائية من بنك يحوي آلاف
الأسئلة دون تحميله كاملاً (استعلام على نقطة عشوائية + التفاف)، وهو ما يحفظ سرعة الاستجابة
المطلوبة في القسم 10.

## 6) القرارات المتّخذة في النقاط المفتوحة (القسم 13 من الـ PRD)

بُنيت هذه النقاط بحيث لا تُقفل أي خيار — كلها قابلة للتغيير من لوحة الأدمن دون تعديل كود:

| النقطة | القرار المطبَّق |
|---|---|
| 1. مدة الاشتراك | **دائم افتراضياً**. الحقل `expiresAt` موجود في النموذج، وتستطيع تحديد مدة بالأيام عند التفعيل اليدوي (الطلاب → اشتراك). الخادم يتحقق من الانتهاء تلقائياً ويحوّل الحالة إلى `expired`. |
| 2. تكرار الاختبار | **مسموح بعدد غير محدود** من المحاولات، مع منع فتح أكثر من اختبار جارٍ في نفس الوقت. |
| 3. الأسعار | **سعر مستقل لكل مادة** (حقل `price`)، والاشتراك يُفعَّل لكل مادة على حدة. |
| 4. الإشعارات | **داخل التطبيق فقط** حالياً (حالة الاشتراك تتحدّث لحظياً عبر `onSnapshot`). البريد/SMS تحسين لاحق. |
| 6. تنسيق ملفات Word | السكربت يعتمد على اللون `C00000` ويتحقق متقاطعاً مع جدول الإجابات إن وُجد، **ويتخطّى** أي سؤال متعارض أو ناقص مع طباعة تحذير صريح بدل إدخال بيانات خاطئة. |
| 7. النطاق | موقع Hosting منفصل `smart-edu-question-bank` ضمن نفس المشروع (قابل للتغيير من `.firebaserc`). |

## 8) لوحة الأبطال — تصميم مختلف عن المستند (معتمَد من صاحب المشروع)

مستند الميزة طلب تخزين `subjectScores` داخل `users/{uid}` والقراءة منه مباشرة. **لم يُنفَّذ
هكذا**، لأن عرض اللوحة يتطلب أن يقرأ كل طالب مستندات بقية الطلاب — وفتح `users` للقراءة كان
سيكشف **بريد وهاتف كل طالب** لأي حساب مسجَّل في المنصة (ومعظمهم قاصرون).

بدلاً من ذلك: مجموعة `leaderboard/{uid}` تحمل **الاسم والصف والنقاط فقط**، تكتبها Cloud
Function التصحيح، ويقرأها الطلاب. جوهر متطلب المستند محفوظ بالكامل: **لا استعلام حي على
`attempts` عند العرض** — القراءة من عدّاد مُجمَّع مسبقاً بـ `FieldValue.increment()` داخل
نفس عملية التصحيح.

| المتطلب | التنفيذ |
|---|---|
| الترتيب تنازلياً حسب الإجابات الصحيحة | `orderBy(FieldPath('subjectScores', subjectId), 'desc').limit(50)` |
| الشارات 🥇1-10 🥈11-20 🥉21-33 | تُحسب من ترتيب القائمة وقت العرض، غير مخزّنة |
| إظهار مركز الطالب دائماً | إن كان خارج الـ50، يُحسب مركزه بـ `getCountFromServer` (عدّاد رخيص لا يقرأ المستندات) |
| لوحة لكل مادة | تبديل بين المواد المفعّلة للطالب فقط |
| اللافتة الترويجية | بارزة لمن هم خارج المراكز الذهبية، ومصغّرة لأول 10 |
| تراكمية دائمة | لا تصفير ولا مواسم |

**ملاحظة على مسار الحقل:** استُخدم `new FieldPath('subjectScores', subjectId)` بدل النص
`'subjectScores.islamic-11-s1'` لأن معرّفات المواد تحتوي شرطات، وتحليل النص كان سيفشل.

**من يظهر على اللوحة:** الطلاب فقط. حسابات الإدارة (`role == 'admin'`) مستثناة داخل
`submitExam` نفسها، حتى لا تتصدّر الاختبارات التجريبية للإدارة لوحة الطلاب.

## 9) أدوات الإدارة المتقدمة

### استيراد ملف Word من المتصفح

زر «استيراد أسئلة» في بطاقة كل مادة → يرفع الملف إلى `imports/{subjectId}/{jobId}.docx` →
ينطلق مشغّل Storage `processQuestionImport` تلقائياً → يستخرج ويكتب → تعرض الواجهة النتيجة
لحظياً عبر متابعة `importJobs/{jobId}`.

| نقطة | تفصيل |
|---|---|
| المنطقة | `us-central1` وحدها (بقية الدوال في `europe-west1`) — مشغّلات Storage تُلزم بمنطقة الحاوية، وحاوية المشروع في US-CENTRAL1. |
| المحلّل | `functions/lib/docx.js` يفكّ ضغط ZIP ويقرأ `word/document.xml`، و`lib/extractQuestions.js` يستخرج الأسئلة (كشف اللون الأحمر، جدول التحقق المتقاطع، التحذيرات). |
| الأرقام العربية | `\d` في JavaScript لا يطابق «٣» — أُضيف تحويل يحافظ على مواضع الأحرف. |
| اللون | أي درجة حمراء تُقبل (وليس `C00000` وحده) — ملفات المعلّمين تستخدم `FF0000` أيضاً، والألوان غير الحمراء تبقى مُتجاهَلة. |
| رقم الدرس | ملف يكتب «الدرس: العنوان» بلا رقم؟ يُلتقط العنوان ويُحسم الرقم من دروس المادة: نفس العنوان ⇐ نفس الرقم (فلا تكرار عند إعادة الاستيراد)، وإلا الرقم التالي. |
| حارس المادة | إن اختلف «مبحث» رأس الملف عن اسم المادة المستهدفة، يظهر تحذير بارز — لمنع رفع ملف مادة إلى بطاقة مادة أخرى. |
| منع التكرار | ببصمة `docId` نفسها في كل الأدوات (تشمل الخيارات) — لا بنص السؤال وحده، وإلا فُقدت أسئلة مشروعة تشترك في النص. |
| الاختبار | `node functions/tests/extract.test.js` (وحدة) و`node scripts/e2e-import-test.js` (المسار كاملاً على مادة تجريبية تُحذف بعده). |

**أول نشر لمشغّل Storage قد يفشل** بخطأ صلاحيات Eventarc لأن حساب الخدمة يُنشأ في نفس اللحظة —
أعد `firebase deploy --only functions:processQuestionImport` بعد دقائق ويمرّ.

### إدارة الأسئلة لكل مادة

`/admin/questions/{subjectId}` — ترقيم صفحات بمؤشرات Firestore (25 لكل صفحة، والصفحات
السابقة محفوظة محلياً فلا تُقرأ مرتين)، فلترة بالدرس، وإضافة/تعديل/حذف سؤال منفرد.

البحث النصي غير مدعوم في Firestore، فتُحمَّل أسئلة المادة مرة واحدة عند أول بحث وتُحفظ للجلسة.
الإضافة والحذف يحدّثان `questionCount` و`lessons` في مستند المادة — واجهة الطالب تعتمد
عليهما كلياً لأنها لا تستطيع قراءة `questions`. والسؤال المُضاف يدوياً يأخذ نفس بصمة المعرّف،
فلا يتكرر إن وصل لاحقاً ضمن ملف Word.

### ترتيب المواد

حقل `displayOrder` وسهما ⬆️⬇️، مع إعادة ترقيم كامل القائمة بعد كل نقلة (تمنع الفجوات والتكرار).

**الفرز يتم في المتصفح لا بـ `orderBy`**، لأن استعلامات orderBy تستبعد المستندات التي لا
تحمل الحقل — وكان ذلك سيُخفي أي مادة أُنشئت قبل الميزة.

## 10) الوضع الفاتح والداكن

كل لون في الموقع يأتي من متغيّر CSS في `src/index.css` — لا قيمة ثابتة واحدة في أي مكوّن.
`tailwind.config.js` يشير للمتغيّرات بصيغة `rgb(var(--x) / <alpha-value>)` فتبقى معدِّلات
الشفافية (`bg-accent/10`) تعمل كما هي.

| نقطة | التفصيل |
|---|---|
| التبديل | `data-theme="light|dark"` على `<html>` |
| منع وميض اللون | سكربت مضمّن في `index.html` يكتب `data-theme` **قبل** تحميل React |
| الافتراضي | `prefers-color-scheme` من نظام التشغيل |
| الاختيار اليدوي | يُحفظ في `localStorage` تحت `sep_theme` وله أولوية دائمة بعده |
| تدرّج `zinc` | مُعاد توجيهه لمتغيّرات ومقلوب في الوضع الفاتح — لذلك تعمل الشاشات الـ20 القائمة دون تعديل أي مكوّن على حدة |

**فروق مقصودة عن وثيقة التصميم** (سببها قياس تباين فعلي بالمتصفح، لا تفضيل شخصي):

| اللون | المستند | المطبَّق | السبب |
|---|---|---|---|
| الذهبي الفاتح | `#b8860b` | `#96690a` | 3.25:1 → 4.86:1 (الحد 4.5:1) |
| الكهرماني الفاتح | `#d6820a` | `#a35f07` | 2.80:1 → 4.71:1 |
| `zinc-500` الداكن | (لم يُذكر) | `#8a8a94` | كان 3.32:1 — خلل سابق للوضع الفاتح |

**الشعار:** قياس `logo.png` أظهر 91% شفافية ومتوسط سطوع 180 وصفر بكسلات داكنة — أي أنه
يكاد يختفي على الخلفية الفاتحة. الحل المطبَّق مؤقّت: لوحة داكنة صغيرة خلفه في الوضع الفاتح
(`.brand-logo`). **البديل الدائم نسخة شعار مخصّصة للوضع الفاتح — قرار تصميمي.**

**تحذير للصيانة:** لا تضع `transition` على `background-color` لعنصر قيمته من متغيّر CSS —
اختُبر فعلياً وبقيت الخلفية عالقة بلون الوضع السابق في Chrome.

## 7) ما لم يُنفَّذ بعد

- **إشعارات البريد الإلكتروني** عند التفعيل (النقطة 4 أعلاه).
